### <span class="imp imp-high" title="Importance 8.5/10" aria-label="Importance 8.5 of 10">8.5</span> N-central zero-day exploits bypass patched servers, enable SYSTEM-level remote code execution
N-able disclosed on November 12, 2026, that security researcher Sean Bales publicly released exploits for new vulnerabilities in N-central on-premise versions running 2026.4.1 HF2. The exploits, codenamed 4EverAble2Shell and Agent2Shell, bypass the patches N-able released on November 10, 2026 (version 2026.4.1.26) to address the earlier Able2Shell vulnerabilities. 4EverAble2Shell enables unauthenticated remote code execution with root privileges on N-central servers. Agent2Shell leverages more than 10 zero-day vulnerabilities to execute commands on managed Windows agents as NT AUTHORITY\SYSTEM, requiring knowledge of the target appliance ID. N-able stated the server issue depends on Legacy API being turned on and exposed to the public internet—a non-default configuration. Legacy API is disabled by default and not recommended for use. The vulnerabilities affect N-central On-premise versions in the Americas, APAC, and Europe regions; hosted environments are not affected. Hosted environments are not impacted. Within hours of the PoC release, threat intelligence firm Previdian observed targeted probing against 4EverAble2Shell from IP 157.20.241.16, with no confirmed successful exploitation reported as of the article date. The observed attack chain combined CVE-2026-90436 (Apache Axis, CVSS 9.8) for initial code execution, 4EverAble2Shell for privilege escalation, and shell script execution via curl. N-able urged customers to disable Legacy API immediately if enabled.

### <span class="imp imp-high" title="Importance 8.5/10" aria-label="Importance 8.5 of 10">8.5</span> Critical Apache HTTP/2 Vulnerability Allows Remote Code Execution
A critical flaw in Apache HTTP Server's mod_http2 module, tracked as CVE-2026-119618, allows unauthenticated remote code execution on affected servers. The vulnerability affects Apache HTTP Server versions 2.4.55 through 2.4.70 and is fixed in version 2.4.71, released November 11, 2026. Only servers with HTTP/2 explicitly enabled via the Protocols directive are affected. Red Hat rates the flaw 9.8 out of 10 on the CVSS scale. An attacker who can reach the server requires no authentication to exploit the vulnerability and could take full control of the server process. Red Hat's assessment states that public research has demonstrated a reliable exploit against a server in its default configuration with mod_http2 enabled, though the company did not name or link that research. Security company Wiz reported that no public exploit was available and no exploitation in the wild had been reported as of November 12, 2026. Standalone builds of the module (mod_h2) released on GitHub are affected from version 2.0.8 through 2.0.42. Apache HTTP Server 2.4.71 also fixes a crash in mod_md rated important and a one-byte stack memory overwrite in mod_vhost_alias rated low. Red Hat Enterprise Linux 9 and 10 shipping their own builds received fixes on November 11, 2026, with Red Hat rating the flaw as Important rather than Critical on those releases due to use of per-stream memory allocators. Red Hat Enterprise Linux 8 and earlier do not contain the vulnerable code.

### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> Google Cloud flags three AMD Turin CPU vulnerabilities allowing cross-process data leakage
Google Cloud identified three CPU side-channel vulnerabilities in AMD Turin processors (fifth-generation AMD EPYC) that could allow attackers with code execution on the same processor core to infer sensitive data from other processes or the kernel within virtual machines. Two of the flaws—TSA-SQ (CVE-2024-36350) and TSA-L1 (CVE-2024-36357)—were initially disclosed July 8, 2025, for earlier EPYC processors, but AMD previously stated Zen 5 CPUs (which include Turin) were not vulnerable to these attacks. AMD has now corrected this statement, saying Turin is "impacted differently from previously characterized AMD processors." The third vulnerability, CVE-2026-0004 (called TSA-Fill by the Xen Project), is newly identified and allows attackers to infer data in the processor's L1 data cache. Google rates the issue Medium severity. Affected machine series are C4D, N4D, H4D, Z4D, and G4, including bare-metal instances of C4D and Z4D. Google has already applied mitigations against cross-VM attacks and between VMs and the host. Remediation requires guests to install OS vendor patches and perform a stop-and-start (not just a reboot) of affected VMs. Google is updating CPU information reported by VMs to enable patched guest kernels to turn on mitigations. As of the bulletin date, neither Google nor AMD reports any exploitation in the wild, and none of the three CVEs are listed in CISA's catalog of exploited vulnerabilities.

### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> Google session hijacking campaign exploits calendar invites and live proxies to steal corporate credentials
Since mid-August 2026, a phishing campaign tracked as Operation CloudFire has been stealing live Google sessions from corporate users. The attack uses Google Calendar invites as the initial lure, with messages arriving via BCC or from organizations the recipient has previously corresponded with. Pretexts include voicemail notifications, RFP/RFI requests, court summonses, and missed payment notices. Most links point to Google itself, routing through Google's /url redirector, share.google, Drive file links, or Intuit transaction notification links. Once clicked, victims encounter a reverse proxy positioned in front of the actual Google sign-in page. Users enter credentials and complete second-factor authentication (SMS codes, authenticator codes, Google Tap-Yes number matching, or phone-based account recovery) while the attacker captures the live session in real time. All second-factor controls are passed through to Google without stopping session capture. The attack uses the Nyasher framework, publicly documented since February 2026. Infrastructure evasion occurs through three layers: Google's trusted redirector, Cloudflare Turnstile challenges (sometimes using real Cloudflare widgets), and dynamically generated password capture pages built in-browser via JavaScript after challenge completion, leaving no static site for scanners to detect. Attack domains were registered days before use, receiving endpoints went live 1-20 days ahead of campaign waves, and wildcard certificates were issued as little as 46 minutes before domain registration. Material Security's Threat Research team identified and took down hundreds of attacker domains in response to the campaign.
