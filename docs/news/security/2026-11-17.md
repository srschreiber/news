### <span class="imp imp-high" title="Importance 8.5/10" aria-label="Importance 8.5 of 10">8.5</span> Critical Java4Shell RCE vulnerability affects Jenkins, Jira, Confluence, Keycloak
Java4Shell, tracked as CVE-2026-114938, is a critical remote code execution vulnerability in OpenJDK discovered on November 17, 2026 with AI assistance. The flaw is rated 9.2 under CVSS 4.0 and allows unauthenticated attackers to corrupt memory and execute code remotely. The vulnerability resides in hand-written x86-64 assembly code used by OpenJDK HotSpot to accelerate Base64 decoding with AVX-512 VBMI instructions. This assembly code bypasses Java's standard memory safeguards. Exploitation requires target-specific profiles and heap grooming, preventing a universal payload. The affected Base64 optimization was shipped to every affected runtime despite benefiting only applications decoding enormous data volumes. OpenJDK and Oracle released fixes on the same day of disclosure. The vulnerability was discovered when researcher Quang Luong directed AI tool Codex to examine the JIT compiler and intrinsics. The flaw affects widely used Java applications including Jenkins, Jira, Confluence, and Keycloak.

### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> Researchers Reveal Workaround to GitHub SHA Pinning Security Defense
Researchers have demonstrated a workaround to SHA pinning, the standard defense mechanism against software supply chain attacks on GitHub Actions. SHA pinning guarantees code immutability but not code provenance—attackers can exploit this by creating malicious commits in forked repositories that pass SHA pinning checks. The technique was used in the March 2026 hijacking of Trivy, a widely used open-source security scanner, where malicious code was planted to appear as an official GitHub checkout tool and labeled as a security fix. The same method was employed in May 2026 against the actions-cool/issues-helper tool, which stole credentials from affected pipelines. The core vulnerability stems from GitHub's fork mechanism: while pinning prevents code from changing, it does not verify authorship or confirm the commit originated from the upstream project. GitHub introduced workflow lockfiles in public preview on October 14, 2026, and made them generally available on October 28, 2026, to address some of these gaps by tying every run to recorded commits for actions and transitive dependencies. However, lockfiles have limitations: they do not verify whether dependencies are safe, do not resolve commit authorship and runtime build concerns, require maintainer opt-in, and are not currently supported on GitHub Enterprise Server.

### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> Google DeepMind Uses AI to Formally Verify Signal Protocol Cryptography
Google DeepMind researchers used agentic AI to formally verify key cryptographic guarantees of the Signal protocol, completing the proof-of-concept work in four weeks. The analysis used a framework called AlphaProof Code, with Gemini Carbon agents generating over six million lines of Lean (a formal verification language) to mathematically prove the protocol's security properties. Human experts reviewed all security goal specifications and audited the proofs, with AI agents flagging approximately one percent of the codebase for human review while automated checking validated the remainder. The analysis found no new vulnerabilities in the Signal protocol portions examined, but successfully identified known vulnerabilities in older versions, demonstrating the verification system's effectiveness. The researchers are releasing the specification and proof to support additional formal verification work. The Signal protocol protects communications on Signal app, Google Messages, and WhatsApp. This work serves as independent validation of cryptography protecting large-scale global communications and demonstrates AI capabilities in formal verification.

### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> GitDoor and GraphDoor Backdoors Abuse GitHub and SharePoint for Command-and-Control
Government sectors in Asia and Africa have been targeted by an active cyber intrusion campaign delivering previously undocumented backdoors that abuse legitimate cloud services for command-and-control. The campaign, codenamed Operation ShadowCloud by Kaspersky, was identified in early 2026. Two modular backdoors, dubbed GraphDoor and GitDoor, leverage Microsoft SharePoint and GitHub respectively for C2 traffic, along with Ably messaging service, allowing the malware to blend in with normal traffic and evade network-based detection. The threat actor abuses the legitimate MeshAgent utility to deploy these backdoors. The attack chain begins with MeshCentral Agent, a legitimate remote access tool, configured to contact a hard-coded C2 server (wss://27.102.66[.]162:443/agent.ashx), which then fetches three payloads: a legitimate binary for DLL sideloading (start.exe, pythonw.exe, zoomit.exe), a rogue loader DLL (jli.dll, SbieDll.dll, python39.dll, WINMM.dll, libcef.dll), and an encrypted file containing the core payload. At least two DLL loader types have been identified—Loader Type 1 uses RC4 stream cipher followed by XOR masking; Loader Type 2 uses XOR operation alone. GitDoor uses two GitHub repositories: a public repository ("/repos/LatonyCharnleyaW/Havo") for receiving commands and a private repository ("/repos/LatonyCharnleyaW/Trix") for uploading execution results. Repository creation dates indicate campaign preparations began by the end of 2024. GitDoor supports 26 commands. Both backdoors employ encryption and obfuscation techniques including control flow flattening and nested helper functions to complicate analysis. An unspecified Taiwanese organization was targeted, with the initial infection vector believed to involve reuse of a prior infection already present on the network. Traffic is proxied using a modified Erfrp client and Ably messaging service-based plugins.

### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> Optimizely Platform Vulnerability Exploited to Distribute Malware on Major Websites
A vulnerability in Optimizely's Web Experimentation platform was exploited to inject malicious JavaScript into customer projects, affecting major websites including BBC, CNN, Zoom, GitLab, Salesforce, Equifax, HSBC, and IKEA. The company identified and patched the vulnerability on November 17, 2026, and removed injected code from affected projects. According to security firm Report URI, which analyzed 1,611 Optimizely scripts, 188 scripts belonging to 178 organizations were infected. The malicious code was placed in an optional JavaScript field that executes on every page, and the tampered files were served from Optimizely's content delivery network, causing browsers to treat them as trusted. The malware could swap cryptocurrency wallet addresses, skim payment card details, collect cookies, and capture page screenshots. By November 16-17, approximately $7,000 in cryptocurrency had been sent to the attacker. iOS users accessing affected sites were served Coruna and DarkSword exploit kits, though successful exploitation was not confirmed.

The exploit framework, called "exploit_agent" and built with Russian-language tools, continuously compared code before and after security patches to identify vulnerabilities and automatically generated working exploit code. Threat actors have weaponized N-day vulnerabilities (patched bugs not yet applied to target systems) to launch large-scale automated attacks on internet-exposed servers. GTIG identified multiple autonomous attack frameworks in active use: Artex, CAIRN, CyberStrikeAI, and PentAGI. The report indicates hackers' techniques have evolved from manual prompt entry to fully autonomous multi-agent attack frameworks, enabling multi-stage intrusions at faster speeds with shrinking human involvement. Beyond exploitation, the report found state-backed threat groups and influence-as-a-service contractors using LLMs to mass-produce synthetic media and automate content distribution, including a case where attackers used the Google Gemini API to manage over 100,000 fake accounts via cloud phone farms.

### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> Cloud credentials in Docker Hub images stolen within seconds
Attackers are automatically extracting and exploiting credentials exposed in public Docker Hub images within seconds of publication. The threat actor TeamPCP, responsible for compromises of Trivy (a vulnerability scanner), Aqua Security's GitHub organizations, LiteLLM, and other open-source projects, has demonstrated rapid exploitation capabilities. In the LiteLLM supply chain compromise on October 21, 2026, malicious version 1.107.0 containing credential-stealing compiled malware was live on PyPI from 11:39 to 13:23 UTC and on Docker Hub from 11:46 to 14:20 UTC. Wiz observed abuse of stolen credentials beginning approximately 4.5 hours after exfiltration. The compromised LiteLLM Docker images included tags v1.107.0, latest, main-latest, and main-stable. LiteLLM receives approximately 23 million weekly downloads. Earlier in March 2026, TeamPCP compromised Trivy versions 0.69.4, 0.69.5, and 0.69.6 on Docker Hub (the last clean release being 0.69.3), containing TeamPCP infostealer indicators. In a separate March 2026 attack on LiteLLM, compromised versions 1.82.7 and 1.82.8 on PyPI (with version 1.82.6 being the last known-clean release) shipped with credential harvesting, Kubernetes lateral movement toolkit, and persistent backdoor capabilities. LiteLLM is a widely-used open-source library with over 95 million monthly downloads that routes requests across LLM providers through a single API. TeamPCP's campaign has crossed five ecosystems: GitHub Actions, Docker Hub, npm (CanisterWorm worm), OpenVSX, and PyPI.

### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> Oracle patches 11 Java vulnerabilities including critical OpenJDK RCE flaw
Oracle released patches on November 17, 2026, for 11 Java SE vulnerabilities with a maximum CVSS 3.1 score of 8.1. All 11 flaws can be exploited remotely without authentication, though Oracle did not disclose their CVE identifiers, affected components, or individual consequences before releasing the patches. Separate reports warn of a potentially critical remote code execution (RCE) flaw in OpenJDK tracked as CVE-2026-114938, assigned a CVSS 4.0 score of 9.2, affecting OpenJDK 17.0.6 and later; however, there is no confirmed evidence this flaw is among the 11 vulnerabilities Oracle patched. Security firm Calif reported discovering the OpenJDK flaw, calling it "Java4Shell," and committed to publishing technical details by 1 p.m. Pacific time on November 17 after Oracle's patch release. Separate analyses by Upwind and Equixly suggest the OpenJDK issue may be a flaw in Java's Base64 decoder causing JVM crashes rather than code execution. Oracle advised customers to stop using Java 8, 11, 17, 21, 25, and 27 current builds and move to replacement releases: Java 8 from 8u511 to 8u513; Java 11 from 11.0.33.0.3 to 11.0.33.1; Java 17 from 17.0.21.0.3 to 17.0.21.1; Java 21 from 21.0.13.0.3 to 21.0.13.1; Java 25 from 25.0.5.0.3 to 25.0.5.1; and Java 27 from 27.0.1.0.3 to 27.0.1.1. Affected Oracle products include Java SE, GraalVM for JDK, GraalVM Enterprise Edition, and JavaFX across multiple versions.
