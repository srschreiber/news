### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> VMware vCenter hit by critical 9.8-rated authentication bypass flaw
Broadcom released patches for 23 vulnerabilities across VMware products (ESX, vCenter, Workstation, Fusion, and Avi Load Balancer) on November 24, 2026. The critical flaw CVE-2026-123903, rated 9.8 on the CVSS scale, is an authentication bypass in the VMware Directory Service (vmdir) that allows a malicious actor with network access to vCenter to bypass authentication and gain unauthorized access. Four additional high-severity vulnerabilities in vCenter were also patched: CVE-2026-123904 (arbitrary file write, CVSS 7.5), CVE-2026-123905 (denial-of-service, CVSS 7.5), CVE-2026-123906 (denial-of-service, CVSS 7.5), and CVE-2026-123907 (denial-of-service, CVSS 7.5). Fixed versions include vCenter 8.0 U3m, vCenter 7.0 (via Broadcom Support), Cloud Foundation 9.1.2, Cloud Foundation 9.0.2.0300, Cloud Foundation 5.2.5, and Telco Cloud Platform versions with vCenter 8.0 U3m. The vulnerability is distinct from the recently patched CVE-2026-123890 (also rated 9.8), another authentication bypass in vmdir that was exploited as a zero-day by suspected China-nexus group Armory Castle. No active exploitation of CVE-2026-123903 has been reported in the wild.

### <span class="imp imp-high" title="Importance 8/10" aria-label="Importance 8 of 10">8</span> WHMCS SQL injection vulnerability exposes customer data and admin password hashes
WHMCS, a billing and automation platform used by web hosting companies, disclosed three SQL injection and related vulnerabilities on November 24, 2026. The most critical flaw, CVE-2026-82981 (CVSS 8.7), requires no authentication and allows attackers to retrieve customer records and administrator password hashes from the database. A second SQL injection, CVE-2026-82979 (CVSS 7.1), requires a logged-in client with View & Manage Contacts permission to access other customers' personal, billing, and support information as well as admin records. A third vulnerability, CVE-2026-93700 (CVSS 9.0), in the email campaign functionality allows logged-in clients to read sensitive configuration files including database credentials and potentially execute code on the server. Fixed versions released November 24 include 9.0.10, 8.13.8, and 9.1.2. Self-hosted administrators must manually update; WHMCS Cloud installations update automatically. For the email campaign flaw, administrators must delete all campaigns and clear the template cache before updating. All three flaws were reported by a single researcher using the handle alakazamspooon. No attacks using these vulnerabilities have been reported. This marks the third round of WHMCS security fixes in 2026, following an authorization flaw in May and an unauthenticated remote code execution flaw in September.

### <span class="imp imp-high" title="Importance 7.5/10" aria-label="Importance 7.5 of 10">7.5</span> Check Point Security Servers Compromised in 22-Organization Campaign
A threat actor tracked as GreyNoise Threat 13 (GT13) has compromised Check Point Security Management servers across at least 22 organizations in a campaign that began in early October 2026 and was likely still ongoing as of November 2026. The campaign targeted organizations in the energy, engineering, financial services, government, manufacturing, mining, and transportation sectors across the US, UK, Australia, Austria, China, France, Germany, Hong Kong, the Netherlands, South Korea, and other geographies. GT13 conducted scanning, exploitation, and control activities from 99 IP addresses, many associated with disposable network infrastructure or compromised victim Check Point devices. The threat actor used AI-enabled offensive tools and agentic harnesses to weaponize vulnerabilities, find vulnerable assets, and automatically exploit them, complemented by hands-on-keyboard activity. Attack activity was confirmed between October 17 and November 2, 2026. The actor deployed tools including Nmap, Chisel, Impacket, Paramiko, and Python utilities to perform reconnaissance, lateral movement, and privilege escalation. GreyNoise documented over 1,400 network sessions, 800+ command line artifacts, and 1,200+ files downloaded, uploaded, or created. Data was exfiltrated from 24 distinct Check Point Security Management servers using a compromised victim server as an operational relay box. In one tracked instance on October 2, the threat actor forged a signed admin session cookie to gain administrative access to an HFS server and obtained SSH access to scan the environment and exfiltrate data. GreyNoise could not determine when or how GT13 initially gained access to the Check Point assets. The campaign does not appear focused on any specific geography or industry sector. GreyNoise has not attributed GT13 to any known publicly tracked threat group and lacks sufficient information to assess actor motivation or nation-of-origin alignment.
