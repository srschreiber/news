### <span class="imp imp-high" title="Importance 7/10" aria-label="Importance 7 of 10">7</span> Compiler Optimizations Can Undermine Security Checks
Compiler optimizations can inadvertently remove or bypass security checks in C code, creating vulnerabilities in binaries despite secure source code, security researcher Chris Domas demonstrated at Black Hat USA 2026. The vulnerability arises because the CPU executes compiler-generated code, with factors like register pressure and data size determining whether nearby code versions are safe or vulnerable.

<ul class="takeaways">
<li>Compilers can delete memory-clearing operations and remove security checks</li>
<li>Time-of-check to time-of-use (TOCTOU) vulnerabilities introduced by optimization</li>
<li>Analysis of 500 million open-source lines identified 300 potentially dangerous patterns</li>
<li>Specific data sizes (e.g., 17 vs. 33 bytes) can flip between safe and vulnerable code</li>
<li>Switching compilers (GCC vs. Clang) alone does not solve the problem</li>
</ul>
